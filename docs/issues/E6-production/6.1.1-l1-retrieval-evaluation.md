# 6.1.1 — L1 Retrieval Evaluation
- **Epic:** E6 Production & Compliance
- **Labels:** `evaluation`, `retrieval`
- **Depends on:** E0.5 Evaluation Runner, 2.1.2 (Hybrid Merge + Reranker)

## Description

实现 L1 Retrieval 层评估 —— 评估检索系统的核心排序与召回质量。该层聚焦于纯检索管道的离线评测，不依赖 Agent 推理环节，确保 Search API 在进入 Agent 消费之前达到基线质量。

**评估指标：**

| 指标 | 公式 | 说明 |
|------|------|------|
| **Recall@K** | \|Retrieved ∩ Relevant\| / \|Relevant\|| 前 K 个结果中召回的相关文档比例 |
| **MRR** (Mean Reciprocal Rank) | 1/N · Σ 1/rank_i | 第一个相关文档排名的倒数均值 |
| **NDCG@K** (Normalized Discounted Cumulative Gain) | DCG@K / IDCG@K | 考虑排序位置和相关度等级的归一化折损累积增益 |

**评估流程：**
```
1. 从 E7 Benchmark 加载 Query + Ground Truth 文档集合
2. 对每个 Query 调用 Hybrid Search（Vector + Keyword + Reranker）
3. 计算 Recall@5 / Recall@10 / MRR / NDCG@5 / NDCG@10
4. 按 source_type 分组统计（CLIENT_DOCUMENT vs AUDIT_STANDARD）
5. 输出 Evaluation Report JSON（EvaluationRunner 标准格式）
6. CI 集成：Recall@10 < 0.85 → PR Blocked
```

**数据来源：** E7 Benchmark（20 Cases × 7 领域）中的检索标注数据。

## Acceptance Criteria

- [ ] `EvaluationRunner` 支持 L1 指标计算：Recall@K (K=5,10)、MRR、NDCG@K (K=5,10)
- [ ] 按 `source_type`（CLIENT_DOCUMENT / AUDIT_STANDARD）分别输出分组指标
- [ ] 每个 Query 输出详细 Hit List（排名、相似度、是否相关、相关度等级）
- [ ] CI 集成：新增检索配置变更（向量维度、HNSW 参数、Reranker 模型）时自动触发 L1 评估
- [ ] Recall@10 < 0.85 时 CI 自动 Block PR
- [ ] Evaluation Report 输出为标准 JSON（符合 `EvaluationRunner` 规范）
- [ ] 支持 A/B 对比模式（两套检索配置的指标并排对比）

## I/O Interface

```yaml
# benchmark/{scenario}/evaluation_l1.yaml
scenario: revenue_audit_v1
layer: L1
queries:
  - query_id: "q_rev_001"
    query_text: "收入确认的审计准则要求"
    ground_truth:
      relevant_doc_ids: ["std_ifrs15_27", "std_isa240_32", "std_isa500_6"]
      relevance_grades: { "std_ifrs15_27": 3, "std_isa240_32": 2, "std_isa500_6": 1 }  # 3=highly relevant
    filters:
      source_types: ["AUDIT_STANDARD"]
```

```python
# L1 Evaluation Result Schema
class L1EvaluationResult(BaseModel):
    query_id: str
    metrics: L1Metrics
    hits: list[HitDetail]

class L1Metrics(BaseModel):
    recall_at_5: float
    recall_at_10: float
    mrr: float
    ndcg_at_5: float
    ndcg_at_10: float

class HitDetail(BaseModel):
    rank: int                # 1-based
    doc_id: str
    score: float             # 相似度分数
    is_relevant: bool
    relevance_grade: int     # 0–3
```

```sql
-- L1 评估结果持久化表
CREATE TABLE evaluation_l1_result (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    benchmark_scenario VARCHAR NOT NULL,
    query_id VARCHAR NOT NULL,
    retrieval_config_hash VARCHAR NOT NULL,  -- 检索配置的版本哈希
    recall_at_5 FLOAT NOT NULL,
    recall_at_10 FLOAT NOT NULL,
    mrr FLOAT NOT NULL,
    ndcg_at_5 FLOAT NOT NULL,
    ndcg_at_10 FLOAT NOT NULL,
    hit_details JSONB NOT NULL,
    evaluated_at TIMESTAMPTZ DEFAULT now()
);
```
