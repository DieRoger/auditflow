# 6.3.1 — Append-Only Audit Log + Hash Chain
- **Epic:** E6 Production & Compliance
- **Labels:** `security`, `compliance`, `audit-log`
- **Depends on:** 0.2.1 (Core Schema + Alembic)

## Description

实现企业级防篡改审计日志系统 —— 三张 Append-Only 表 + SHA-256 Hash Chain，满足 ISA 230（审计文档）和 CPA 执业准则对审计工作底稿完整性（integrity）和不可篡改性（immutability）的合规要求。

**核心设计：**

1. **Append-Only 三张表：** `agent_execution_log` / `approval_log` / `document_access_log`，数据库层面 `REVOKE UPDATE, DELETE`，仅允许 `INSERT + SELECT`
2. **Hash Chain：** 每行包含 `payload_hash = SHA256(payload::text)` 和 `previous_hash`（指向前一行），任何行的 payload 被修改、行被删除或插入，都会导致链断裂
3. **完整性验证函数：** `verify_hash_chain(workflow_id)` 重算整个链，输出每个表的验证结果
4. **审批快照：** `approval_log.artifact_snapshot` 保存审批时刻的完整 Artifact JSON，即使后续重新执行，决策依据不可丢失

**Hash Chain 原理：**
```
Row 1:  payload_hash = SHA256(payload_1),  previous_hash = NULL
Row 2:  payload_hash = SHA256(payload_2),  previous_hash = SHA256(payload_1)
Row 3:  payload_hash = SHA256(payload_3),  previous_hash = SHA256(payload_2)
  ...
Row N:  payload_hash = SHA256(payload_N),  previous_hash = SHA256(payload_{N-1})

验证：对每行重新计算 payload_hash，并检查 previous_hash 是否匹配上一行的 payload_hash
```

## Acceptance Criteria

- [ ] `agent_execution_log` 表创建（含完整 CHECK 约束、索引、REVOKE UPDATE/DELETE）
- [ ] `approval_log` 表创建（含 `artifact_snapshot` JSONB、CHECK 约束、索引、REVOKE UPDATE/DELETE）
- [ ] `document_access_log` 表创建（含 `ip_address` INET、CHECK 约束、索引、REVOKE UPDATE/DELETE）
- [ ] `verify_hash_chain(workflow_id)` 函数实现（对三张表逐一验证，返回 `table_name / total_rows / verified_rows / first_break_at / is_valid`）
- [ ] 应用层 `compute_next_hash()` 工具函数（SHA-256 计算 + 查询上一条 `payload_hash`）
- [ ] 所有 Agent 执行事件自动写入 `agent_execution_log`（AgentStarted / ToolCalled / AgentCompleted / AgentFailed / ArtifactCreated 等 9 种事件类型）
- [ ] 每次人工审批提交自动写入 `approval_log`（含完整 `artifact_snapshot`）
- [ ] 每次文档上传/下载/预览自动写入 `document_access_log`
- [ ] Alembic migration 脚本（`REVOKE UPDATE, DELETE` 在 migration 中执行）
- [ ] 单元测试：正常链验证通过、篡改检测、插入检测、删除检测
- [ ] 存储增长预估文档（日均 50 Workflow → 年 18 GB → 按年分区策略）

```sql
CREATE TABLE agent_execution_log (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    workflow_id     UUID        NOT NULL,
    agent_name      VARCHAR(64) NOT NULL,
    prompt_version  VARCHAR(32) NOT NULL,
    event_type      VARCHAR(32) NOT NULL,   -- AGENT_STARTED | TOOL_CALLED | ... | AGENT_FAILED (9 种)
    payload         JSONB       NOT NULL,
    payload_hash    VARCHAR(64) NOT NULL,   -- SHA-256(payload::text)
    previous_hash   VARCHAR(64),           -- 同一 workflow 上一条的 payload_hash
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
    CONSTRAINT chk_agent_exec_event_type CHECK (
        event_type IN (
            'AGENT_STARTED', 'AGENT_THINKING',
            'TOOL_CALLED', 'TOOL_COMPLETED',
            'AGENT_COMPLETED', 'AGENT_FAILED',
            'ARTIFACT_CREATED', 'RETRIEVAL_COMPLETED',
            'EVIDENCE_FOUND'
        )
    )
);

REVOKE UPDATE, DELETE ON agent_execution_log FROM PUBLIC;
REVOKE UPDATE, DELETE ON agent_execution_log FROM auditflow_app;

    previous_hash    VARCHAR(64),
```

```sql
RETURNS TABLE (
    table_name       TEXT,

)
LANGUAGE plpgsql STABLE;

-- 调用示例
SELECT * FROM verify_hash_chain('a1b2c3d4-5678-90ab-cdef-1234567890ab');
-- 预期输出（正常）：agent_execution_log | 142 | 142 | NULL | t
--                    approval_log        |   3 |   3 | NULL | t
--                    document_access_log |  18 |  18 | NULL | t
```

```python
# 应用层写入逻辑（见 ADR-004 §5）
import hashlib, json

async def compute_next_hash(
    db: AsyncSession,
    table_name: str,
    workflow_id: UUID,
    payload: dict,
) -> tuple[str, str | None]:
    """计算 payload_hash 和 previous_hash。"""
    payload_text = json.dumps(payload, sort_keys=True, ensure_ascii=False)
    payload_hash = hashlib.sha256(payload_text.encode()).hexdigest()

    result = await db.execute(
        text(f"SELECT payload_hash FROM {table_name} "
             "WHERE workflow_id = :wid "
             "ORDER BY created_at DESC, id DESC LIMIT 1"),
        {"wid": workflow_id},
    )
    previous_hash = result.scalar()
    return payload_hash, previous_hash
```
