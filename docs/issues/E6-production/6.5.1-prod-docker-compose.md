# 6.5.1 — Prod Docker Compose
- **Epic:** E6 Production & Compliance
- **Labels:** `infra`, `deployment`
- **Depends on:** 0.1.2 (Docker Compose 开发环境)

## Description

在开发环境 `docker-compose.yml` 基础上，构建生产级 `docker-compose.prod.yml`，面向单机/单 VM 部署场景（MVP Beta 不包含 K8s）。

**与开发环境的差异：**

| 关注点 | 开发环境 (0.1.2) | 生产环境 (6.5.1) |
|--------|-----------------|-------------------|
| **FastAPI** | `--reload` hot-reload | `gunicorn + uvicorn workers`（多 worker） |
| **PostgreSQL** | 单实例，无持久化 | Named volume 持久化 + `pgbouncer` 连接池 |
| **Redis** | 单实例 | 持久化（AOF）+ `redis-exporter` |
| **MinIO** | 单节点 | 持久化 volume |
| **资源限制** | 无 | CPU / Memory limits（`deploy.resources`） |
| **健康检查** | 基础 `healthcheck` | 生产级 `healthcheck`（含间隔/超时/重试） |
| **日志** | stdout | JSON 格式 stdout + `promtail` → Loki（可选） |
| **网络** | 单 bridge | 隔离网络（`frontend` / `backend` / `storage`） |
| **重启策略** | `unless-stopped` | `unless-stopped` + `restart: always` 对关键服务 |

**服务清单：**
- `api`（FastAPI + gunicorn + uvicorn workers）
- `worker`（Celery worker × 2 并发）
- `postgres`（PG15 + PGVector + pgbouncer sidecar）
- `redis`（7.x + AOF 持久化）
- `minio`（对象存储）
- `nginx`（反向代理 + 静态资源 + rate limiting）
- `otel-collector` + `jaeger` + `prometheus` + `grafana`（可选 profile）

## Acceptance Criteria

- [ ] `docker-compose.prod.yml` 所有服务定义完整
- [ ] `api` 服务使用 `gunicorn` + `uvicorn.workers.UvicornWorker`（`--workers 4`）
- [ ] PostgreSQL named volume（`pgdata`），重启不丢数据
- [ ] Redis AOF 持久化（`appendonly yes`）
- [ ] 所有服务配置 `deploy.resources.limits`（CPU + Memory）
- [ ] 所有服务配置 `healthcheck`（`interval: 30s, timeout: 10s, retries: 3`）
- [ ] `nginx.conf` 含反向代理规则 + `/api/` 路由 + 静态资源缓存 + rate limiting（`limit_req_zone`）
- [ ] `.env.production.example` 含所有生产级环境变量
- [ ] `make prod-up` / `make prod-down` 便捷命令
- [ ] 生产部署文档（`docs/deployment/production.md`）
- [ ] `docker compose -f docker-compose.prod.yml up -d` 一键启动成功

## I/O Interface

```yaml
# deploy/production/docker-compose.prod.yml（核心结构）
version: "3.9"

networks:
  frontend:
  backend:
  storage:

volumes:
  pgdata:
  redis_data:
  minio_data:

services:
  # ── API ────────────────────────────────────────
  api:
    build:
      context: ../..
      dockerfile: Dockerfile
      target: production                      # 多阶段构建：production target
    command:
      - gunicorn
      - -k uvicorn.workers.UvicornWorker
      - -w 4
      - --bind 0.0.0.0:8000
      - --access-logfile -
      - --error-logfile -
      - app.main:app
    env_file:
      - ../../.env.production
    deploy:
      resources:
        limits:
          cpus: "2"
          memory: "2G"
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:8000/health"]
      interval: 30s
      timeout: 10s
      retries: 3
    networks:
      - backend
      - frontend
    restart: always

  # ── Worker ─────────────────────────────────────
  worker:
    build:
      context: ../..
      dockerfile: Dockerfile
      target: production
    command: ["celery", "-A", "app.worker", "worker", "--concurrency=2", "--loglevel=info"]
    env_file:
      - ../../.env.production
    deploy:
      resources:
        limits:
          cpus: "1"
          memory: "1G"
    networks:
      - backend
      - storage
    restart: always

  # ── PostgreSQL ─────────────────────────────────
  postgres:
    image: pgvector/pgvector:pg15
    env_file:
      - ../../.env.production
    volumes:
      - pgdata:/var/lib/postgresql/data
      - ./init-prod.sql:/docker-entrypoint-initdb.d/init.sql
    deploy:
      resources:
        limits:
          cpus: "2"
          memory: "4G"
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U auditflow"]
      interval: 10s
      timeout: 5s
      retries: 5
    networks:
      - backend
      - storage
    restart: always

  # ── pgbouncer ──────────────────────────────────
  pgbouncer:
    image: edoburu/pgbouncer:1.21
    environment:
      - DB_HOST=postgres
      - DB_USER=auditflow
      - POOL_MODE=transaction
      - MAX_CLIENT_CONN=100
      - DEFAULT_POOL_SIZE=25
    env_file:
      - ../../.env.production                   # DB_PASSWORD
    networks:
      - backend
    restart: always

  # ── Redis ──────────────────────────────────────
  redis:
    image: redis:7-alpine
    command: ["redis-server", "--appendonly", "yes", "--requirepass", "${REDIS_PASSWORD}"]
    volumes:
      - redis_data:/data
    deploy:
      resources:
        limits:
          cpus: "0.5"
          memory: "512M"
    healthcheck:
      test: ["CMD", "redis-cli", "--raw", "ping"]
      interval: 10s
      timeout: 3s
      retries: 5
    networks:
      - backend
      - storage
    restart: always

  # ── MinIO ──────────────────────────────────────
  minio:
    image: minio/minio:latest
    command: ["server", "/data", "--console-address", ":9001"]
    env_file:
      - ../../.env.production
    volumes:
      - minio_data:/data
    deploy:
      resources:
        limits:
          cpus: "1"
          memory: "1G"
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:9000/minio/health/live"]
      interval: 30s
      timeout: 10s
      retries: 3
    networks:
      - backend
      - storage
    restart: always

  # ── Nginx ──────────────────────────────────────
  nginx:
    image: nginx:1.25-alpine
    volumes:
      - ./nginx.conf:/etc/nginx/nginx.conf:ro
    ports:
      - "80:80"
      - "443:443"
    depends_on:
      - api
    deploy:
      resources:
        limits:
          cpus: "0.5"
          memory: "256M"
    networks:
      - frontend
    restart: always
```

```nginx
# deploy/production/nginx.conf（核心结构）
upstream api_backend {
    server api:8000;
}

server {
    listen 80;
    server_name _;

    # 全局 rate limiting：100 req/s per IP
    limit_req_zone $binary_remote_addr zone=global:10m rate=100r/s;
    limit_req zone=global burst=20 nodelay;

    # 静态资源（React build）
    location / {
        root /usr/share/nginx/html;
        try_files $uri /index.html;
        expires 30d;
    }

    # API 反向代理
    location /api/ {
        limit_req zone=global burst=50 nodelay;
        proxy_pass http://api_backend;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_read_timeout 300s;  # Agent 执行可能较长
    }

    # WebSocket（Workflow 实时推送）
    location /ws/ {
        proxy_pass http://api_backend;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "Upgrade";
        proxy_read_timeout 86400s;
    }
}
```
