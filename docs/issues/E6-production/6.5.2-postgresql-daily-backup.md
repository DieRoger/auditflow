# 6.5.2 — PostgreSQL 每日备份
- **Epic:** E6 Production & Compliance
- **Labels:** `infra`, `backup`
- **Depends on:** 0.2.1 (Core Schema), 6.5.1 (Prod Docker Compose)

## Description

实现 PostgreSQL 数据库的自动化每日备份策略，满足审计行业对数据保留和灾难恢复的合规要求（ISA 230 要求审计文档保存不少于 5 年，本系统保留 90 天滚动窗口）。

**备份策略：**

| 参数 | 值 | 说明 |
|------|-----|------|
| **备份频率** | 每日 02:00 UTC | 低峰期执行，不影响审计业务 |
| **保留天数** | 90 天 | 滚动窗口，超过 90 天的自动清理 |
| **备份类型** | `pg_dump` 自定义格式（压缩） | `--format=custom` + `--compress=9` |
| **备份内容** | 完整数据库（schema + data） | 不含 `pgvector` 索引（索引重建更快） |
| **存储位置** | MinIO bucket `db-backups` | 与主存储隔离 |
| **加密** | AES-256（MinIO Server-Side Encryption） | 备份文件在存储层加密 |
| **完整性校验** | SHA-256 checksum | 备份完成后生成 `.sha256` 文件 |
| **监控** | Prometheus `backup_success` 指标 | 备份失败 → Grafana Alert |

**备份脚本流程：**
```
1. pg_dump → /tmp/auditflow_YYYYMMDD_HHMMSS.dump.gz
2. SHA-256 checksum → /tmp/auditflow_YYYYMMDD_HHMMSS.dump.gz.sha256
3. 上传到 MinIO: db-backups/YYYY/MM/DD/auditflow_YYYYMMDD_HHMMSS.dump.gz
4. 验证上传完整性（对比本地 SHA-256 vs MinIO ETag）
5. 清理本地临时文件
6. 清理 MinIO 中超过 90 天的备份
7. 写入 Prometheus pushgateway: backup_success=1 或 backup_failure=1
```

**恢复流程（文档化）：**
```
1. 从 MinIO 下载目标备份文件
2. SHA-256 校验完整性
3. pg_restore --clean --if-exists -d auditflow auditflow_YYYYMMDD.dump.gz
4. 重建 pgvector 索引（CREATE INDEX ... USING hnsw）
5. 验证恢复：行数对比 / verify_hash_chain()
```

## Acceptance Criteria

- [ ] 备份脚本 `scripts/backup-db.sh`（含错误处理 + 退出码）
- [ ] Cron job 配置（容器内 `supercronic` 或宿主机 crontab）
- [ ] `pg_dump --format=custom --compress=9` 排除 `pgvector` 索引
- [ ] 上传到 MinIO `db-backups` bucket（自动创建 bucket 如果不存在）
- [ ] SHA-256 checksum 生成 + 上传 `.sha256` 校验文件
- [ ] 90 天过期备份自动清理（MinIO Object Lifecycle Policy 或脚本清理）
- [ ] Prometheus `backup_success` / `backup_failure` 指标推送
- [ ] Grafana Alert：连续 2 天 `backup_success=0` → 告警
- [ ] 恢复文档 `docs/operations/disaster-recovery.md`（含完整恢复步骤）
- [ ] 恢复演练：手动执行一次恢复流程并验证数据完整性

## I/O Interface

```bash
#!/bin/bash
# scripts/backup-db.sh
# PostgreSQL 每日备份脚本 — 由 cron 每日凌晨 02:00 UTC 触发

set -euo pipefail

# ── 配置 ──────────────────────────────────────────
DB_HOST="${DB_HOST:-postgres}"
DB_PORT="${DB_PORT:-5432}"
DB_NAME="${DB_NAME:-auditflow}"
DB_USER="${DB_USER:-auditflow}"
DB_PASSWORD="${DB_PASSWORD:?DB_PASSWORD must be set}"

MINIO_ENDPOINT="${MINIO_ENDPOINT:-minio:9000}"
MINIO_BUCKET="${MINIO_BUCKET:-db-backups}"
MINIO_ACCESS_KEY="${MINIO_ACCESS_KEY:?MINIO_ACCESS_KEY must be set}"
MINIO_SECRET_KEY="${MINIO_SECRET_KEY:?MINIO_SECRET_KEY must be set}"

RETENTION_DAYS="${RETENTION_DAYS:-90}"
PROMETHEUS_PUSHGATEWAY="${PROMETHEUS_PUSHGATEWAY:-pushgateway:9091}"

TIMESTAMP=$(date -u +"%Y%m%d_%H%M%S")
BACKUP_FILE="auditflow_${TIMESTAMP}.dump.gz"
CHECKSUM_FILE="${BACKUP_FILE}.sha256"
LOCAL_DIR="/tmp/db-backups"

# ── 函数：推送 Prometheus 指标 ──────────────────
push_metric() {
    local metric_name="$1"
    local metric_value="$2"
    cat <<EOF | curl -s --data-binary @- "${PROMETHEUS_PUSHGATEWAY}/metrics/job/db_backup"
# TYPE ${metric_name} gauge
${metric_name} ${metric_value}
EOF
}

# ── 1. 创建本地临时目录 ──────────────────────────
mkdir -p "${LOCAL_DIR}"

# ── 2. pg_dump ────────────────────────────────────
export PGPASSWORD="${DB_PASSWORD}"
echo "[$(date)] Starting pg_dump..."

if ! pg_dump \
    --host="${DB_HOST}" \
    --port="${DB_PORT}" \
    --username="${DB_USER}" \
    --dbname="${DB_NAME}" \
    --format=custom \
    --compress=9 \
    --no-owner \
    --no-acl \
    --file="${LOCAL_DIR}/${BACKUP_FILE}" \
    2>&1; then

    echo "[$(date)] ERROR: pg_dump failed"
    push_metric "backup_success" 0
    push_metric "backup_failure" 1
    exit 1
fi

echo "[$(date)] pg_dump complete: ${LOCAL_DIR}/${BACKUP_FILE} ($(du -h ${LOCAL_DIR}/${BACKUP_FILE} | cut -f1))"

# ── 3. SHA-256 checksum ───────────────────────────
sha256sum "${LOCAL_DIR}/${BACKUP_FILE}" > "${LOCAL_DIR}/${CHECKSUM_FILE}"
echo "[$(date)] SHA-256: $(cat ${LOCAL_DIR}/${CHECKSUM_FILE})"

# ── 4. 上传到 MinIO ───────────────────────────────
YEAR=$(date -u +"%Y")
MONTH=$(date -u +"%m")
DAY=$(date -u +"%d")
MINIO_PATH="db-backups/${YEAR}/${MONTH}/${DAY}"

# 使用 mc (MinIO Client) 上传
mc alias set minio "http://${MINIO_ENDPOINT}" "${MINIO_ACCESS_KEY}" "${MINIO_SECRET_KEY}"

# 确保 bucket 存在
mc mb --ignore-existing "minio/${MINIO_BUCKET}"

# 上传备份文件
mc cp "${LOCAL_DIR}/${BACKUP_FILE}" "minio/${MINIO_BUCKET}/${MINIO_PATH}/${BACKUP_FILE}"
mc cp "${LOCAL_DIR}/${CHECKSUM_FILE}" "minio/${MINIO_BUCKET}/${MINIO_PATH}/${CHECKSUM_FILE}"

echo "[$(date)] Uploaded to MinIO: ${MINIO_BUCKET}/${MINIO_PATH}/${BACKUP_FILE}"

# ── 5. 验证上传完整性 ─────────────────────────────
REMOTE_CHECKSUM=$(mc cat "minio/${MINIO_BUCKET}/${MINIO_PATH}/${CHECKSUM_FILE}" | cut -d' ' -f1)
LOCAL_CHECKSUM=$(cut -d' ' -f1 "${LOCAL_DIR}/${CHECKSUM_FILE}")

if [ "${REMOTE_CHECKSUM}" != "${LOCAL_CHECKSUM}" ]; then
    echo "[$(date)] ERROR: Checksum mismatch after upload"
    push_metric "backup_success" 0
    push_metric "backup_failure" 1
    exit 1
fi

echo "[$(date)] Upload integrity verified"

# ── 6. 清理本地临时文件 ───────────────────────────
rm -f "${LOCAL_DIR}/${BACKUP_FILE}" "${LOCAL_DIR}/${CHECKSUM_FILE}"

# ── 7. 清理过期备份（MinIO） ─────────────────────
CUTOFF_DATE=$(date -u -d "${RETENTION_DAYS} days ago" +"%Y-%m-%d")
echo "[$(date)] Cleaning backups older than ${CUTOFF_DATE}..."

mc rm --recursive --older-than "${RETENTION_DAYS}d" "minio/${MINIO_BUCKET}/db-backups/" 2>/dev/null || true

# ── 8. 成功指标 ───────────────────────────────────
echo "[$(date)] Backup completed successfully: ${BACKUP_FILE}"
push_metric "backup_success" 1
push_metric "backup_failure" 0
```

```yaml
# deploy/production/prometheus-alerts-backup.yml
groups:
  - name: db_backup
    rules:
      - alert: DatabaseBackupFailed
        expr: backup_success == 0
        for: 2d  # 连续两天失败才告警（容忍偶发失败）
        labels:
          severity: critical
        annotations:
          summary: "PostgreSQL 每日备份连续 2 天失败"
          description: "最近一次成功备份在 {{ 2 | humanizeDuration }} 之前，请立即检查备份脚本和 MinIO 连接。"
```
