# 6.1.2 — L2 Agent Evaluation
- **Epic:** E6 Production & Compliance
- **Labels:** `evaluation`, `agent`
- **Depends on:** E0.5 Evaluation Runner, E3 Agent Core (3.2.1–3.2.5)

## Description

实现 L2 Agent 层评估 —— 对 5 个 Agent 各自的输出质量进行独立评测。每个 Agent 有专属的评估指标，评估数据来自 E7 Benchmark 中按 Agent 标注的 expected output。

**各 Agent 的 L2 评估指标：**

| Agent | 指标 | 说明 | 目标 |
|-------|------|------|------|
| **Planner** | Plan Completeness | 审计计划覆盖的 Risk Area / 预期总数 | ≥ 0.80 |
| | Ontology Alignment | 计划步骤与 Ontology 推理链的匹配度 | ≥ 0.75 |
| **Knowledge** | Standard Retrieval Precision@5 | 检索到的准则条款中相关的比例 | ≥ 0.80 |
| | Citation Accuracy | 引用的准则条款号与实际内容一致 | ≥ 0.90 |
| **Risk** | Risk Classification Accuracy | 正确识别的风险领域数 / 标注风险总数 | ≥ 0.85 |
| | Severity Accuracy | 严重程度正确的风险数 / 标注风险总数 | ≥ 0.75 |
| | Reasoning Quality | LLM-as-Judge 评估推理链质量（1–5 Likert） | ≥ 3.5 |
| **Evidence** | Evidence Coverage | 有证据支持的 Claim / 总 Claim | ≥ 0.80 |
| | Citation Source Accuracy | 引用源文档位置与实际内容匹配 | ≥ 0.85 |
| **Reviewer** | Issue Detection Rate | 检测到的真实问题 / 标注问题总数 | ≥ 0.80 |
| | False Positive Rate | 误报数 / 总检出数 | ≤ 0.15 |

**评估流程：**
```
1. 加载 E7 Benchmark Case（含 Agent-specific expected output）
2. 对每个 Case 调用 Agent.execute() → 获取 Artifact
3. 将 Agent 产出 vs expected 输入对应 Metric 计算器
4. 自动评分（Risk/Knowledge/Evidence）+ LLM-as-Judge（Reasoning Quality）
5. 聚合 per-Agent 分数 → L2 Evaluation Report
6. CI 集成：任一核心指标低于基线 → PR Blocked
```

## Acceptance Criteria

- [ ] `EvaluationRunner` 支持 L2 指标计算（per Agent 的 11 项指标）
- [ ] LLM-as-Judge 评分器用于 Reasoning Quality（含评分 Rubric 提示词）
- [ ] 支持 Agent 级 A/B 对比（Prompt v1 vs v2 在同一 Case 上的指标差异）
- [ ] CI 集成：Agent Prompt 变更时自动触发对应 Agent 的 L2 评估
- [ ] 任一核心指标低于 Baseline → CI 自动 Block PR
- [ ] L2 Report 含 per-Case 明细（每个 Case 的每项指标得分 + 失败原因摘要）
- [ ] 区分 "Agent 模型变更" vs "Prompt 变更" 对指标的影响（Prompt Version Evaluation）

## I/O Interface

```yaml
# benchmark/{scenario}/evaluation_l2.yaml
scenario: revenue_audit_v1
layer: L2
cases:
  - case_id: "rev_001"
    agent_name: "Risk"
    input:
      evidence_package_id: "bench_ep_rev001"
      knowledge_package_id: "bench_kp_rev001"
    expected:
      risk_findings:
        - area: "Revenue Recognition"
          severity: "HIGH"
          indicators: ["revenue_growth > 3x avg", "receivable_days increased >30% YoY"]
      assertions: ["Existence", "Accuracy", "Cutoff"]
      related_standards: ["IFRS 15 ¶27", "ISA 240 ¶32"]
```

```python
# L2 Evaluation Result Schema
class L2EvaluationResult(BaseModel):
    case_id: str
    agent_name: str
    prompt_version: str
    model: str                        # 使用的 LLM 模型（用于 Prompt/Model 归因分离）
    metrics: L2AgentMetrics
    passed: bool
    failure_reasons: list[str]        # 未通过指标的具体原因

class L2AgentMetrics(BaseModel):
    # Planner
    plan_completeness: float | None = None
    ontology_alignment: float | None = None
    # Knowledge
    standard_precision_at_5: float | None = None
    citation_accuracy: float | None = None
    # Risk
    risk_classification_accuracy: float | None = None
    severity_accuracy: float | None = None
    reasoning_quality: float | None = None       # LLM-as-Judge（1–5）
    # Evidence
    evidence_coverage: float | None = None
    citation_source_accuracy: float | None = None
    # Reviewer
    issue_detection_rate: float | None = None
    false_positive_rate: float | None = None
```

```sql
-- L2 评估结果持久化表
CREATE TABLE evaluation_l2_result (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    case_id VARCHAR NOT NULL,
    agent_name VARCHAR NOT NULL,
    prompt_version VARCHAR NOT NULL,
    model VARCHAR NOT NULL,
    metrics JSONB NOT NULL,            -- L2AgentMetrics 序列化
    passed BOOLEAN NOT NULL,
    failure_reasons JSONB DEFAULT '[]',
    evaluated_at TIMESTAMPTZ DEFAULT now()
);

CREATE INDEX idx_eval_l2_agent ON evaluation_l2_result (agent_name, evaluated_at DESC);
CREATE INDEX idx_eval_l2_case ON evaluation_l2_result (case_id);
```
