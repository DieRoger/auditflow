# 6.2.1 — OpenTelemetry + Prometheus + Grafana
- **Epic:** E6 Production & Compliance
- **Labels:** `observability`, `infra`
- **Depends on:** 0.1.2 (Docker Compose 开发环境), 0.3.3 (Logging & Telemetry)

## Description

建立生产级可观测性体系 —— 全链路 Trace + 指标采集 + 可视化 Dashboard + 告警规则。在 0.3.3（structlog + trace_id）的基础上，接入 OpenTelemetry 生态，实现：

1. **全链路分布式追踪（Tracing）：** 每个 API 请求 → Agent 执行 → Tool 调用 → LLM API 调用的完整 Span 树
2. **指标采集（Metrics）：** 请求 QPS、延迟分位数（P50/P95/P99）、错误率、Token 消耗、Agent 执行时长
3. **Dashboard（Grafana）：** 预置 3 张 Dashboard — API Overview / Agent Runtime / LLM Cost
4. **告警（Alerting）：** P95 延迟 > 5s / 错误率 > 5% / Token 日消耗超预算 → 企业微信 / Slack / Email

**技术栈：**
- **OpenTelemetry SDK**（Python `opentelemetry-api` + `opentelemetry-sdk`）→ 自动/手动 Instrumentation
- **OTLP Collector** → 接收 Traces + Metrics → 导出到 Jaeger + Prometheus
- **Jaeger** → Trace 存储与查询
- **Prometheus** → Metrics 时序存储
- **Grafana** → Dashboard + Alerting

## Acceptance Criteria

- [ ] 所有 FastAPI endpoint 自动 Span（`opentelemetry-instrumentation-fastapi`）
- [ ] 所有 Agent 执行自动 Span（`agent_name` / `workflow_id` / `prompt_version` 作为 Span Attributes）
- [ ] LLM API 调用自动 Span（`model` / `tokens` / `latency_ms` 作为 Span Attributes）
- [ ] `trace_id` 从 structlog JSON 日志到 Jaeger Trace 全链路打通（日志中可跳转到 Trace）
- [ ] Prometheus Metrics：
  - `http_requests_total`（按 endpoint / status_code）
  - `http_request_duration_seconds`（P50/P95/P99 histogram）
  - `agent_execution_duration_seconds`（按 agent_name）
  - `llm_token_consumption_total`（按 model）
  - `llm_api_errors_total`（按 model / error_type）
- [ ] Grafana Dashboard 3 张（JSON 预置在 `deploy/grafana/dashboards/`）：
  - **API Overview：** QPS / P95 Latency / Error Rate / 4xx vs 5xx
  - **Agent Runtime：** per-Agent 执行时长 / 成功率 / HITL 触发率 / 迭代次数分布
  - **LLM Cost：** Token 消耗趋势 / 按模型成本 / 日/周/月预算达成率
- [ ] 告警规则（`deploy/prometheus/alerts.yml`）：
  - `HighLatency`：P95 > 5s 持续 5min
  - `HighErrorRate`：错误率 > 5% 持续 5min
  - `TokenBudgetExceeded`：日 Token 消耗 > 预算 80% → Warning / > 100% → Critical
- [ ] Docker Compose 中一键启动（`docker compose --profile observability up -d`）

```python
# 应用层 OpenTelemetry 初始化（app/core/telemetry.py）
from opentelemetry import trace
from opentelemetry.exporter.otlp.proto.grpc.trace_exporter import OTLPSpanExporter
from opentelemetry.sdk.trace import TracerProvider
from opentelemetry.sdk.trace.export import BatchSpanProcessor
from opentelemetry.instrumentation.fastapi import FastAPIInstrumentor
from opentelemetry.instrumentation.httpx import HTTPXClientInstrumentor

def init_telemetry(app: FastAPI, service_name: str = "auditflow"):
    # 1. Tracer Provider
    provider = TracerProvider()
    exporter = OTLPSpanExporter(endpoint="http://otel-collector:4317")
    provider.add_span_processor(BatchSpanProcessor(exporter))
    trace.set_tracer_provider(provider)

    # 2. Auto-instrumentation
    FastAPIInstrumentor.instrument_app(app)
    HTTPXClientInstrumentor().instrument()
```

```python
# Agent Span 手动埋点示例
from opentelemetry import trace

tracer = trace.get_tracer(__name__)

async def execute_agent(agent_name: str, request: AgentRequest):
    with tracer.start_as_current_span(
        f"agent.{agent_name}.execute",
        attributes={
            "agent.name": agent_name,
            "workflow.id": request.workflow_id,
            "prompt.version": request.context.get("prompt_version"),
        },
    ) as span:
        result = await agent.run(request)
        span.set_attribute("agent.status", result.status)
        span.set_attribute("agent.confidence", result.confidence)
        span.set_attribute("agent.tokens", result.metrics.get("total_tokens", 0))
        return result
```
