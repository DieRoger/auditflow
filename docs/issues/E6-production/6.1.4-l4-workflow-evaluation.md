# 6.1.4 — L4 Workflow Evaluation
- **Epic:** E6 Production & Compliance
- **Labels:** `evaluation`, `workflow`
- **Depends on:** E4 Audit Services (4.1.1–4.2.1)

## Description

实现 L4 Workflow 层评估 —— 对整个审计工作流的端到端质量进行评估。L4 是四层体系中的最顶层，衡量系统在真实审计场景中的整体效率和效果，而非单个组件。

**评估指标：**

| 指标 | 说明 | 目标 |
|------|------|------|
| **Completion Rate** | 无需人工干预即完成的工作流占比 | ≥ 0.70 |
| **Human Intervention Count** | 每个 Workflow 平均触发人工审批次数 | ≤ 2 |
| **Time Reduction** | 相比纯人工审计的时间压缩比 | ≥ 3x |
| **End-to-End Accuracy** | Workflow 最终结论与标注结论一致的比例 | ≥ 0.80 |
| **First-Pass Yield** | 一次通过 Reviewer 无需 Revision 的 Workflow 占比 | ≥ 0.60 |

**评估流程：**
```
1. 加载 E7 Benchmark 中的端到端审计 Case（完整输入 + expected final output）
2. 执行完整 Workflow：Planner → Knowledge → Risk → Evidence → Reviewer → HITL
3. 记录全链路指标：
   - 各 Agent 执行时间 / tokens / cost
   - HITL 触发次数与原因
   - Reviewer 退回次数
   - 最终结论 vs 标注结论对比
4. 聚合 L4 指标 → L4 Evaluation Report
5. 与 Baseline（纯人工 / GPT-4 Direct / Naive RAG）对比
```

**数据来源：** E7 Benchmark 中的 End-to-End Cases（每个领域至少 1 个端到端 Case）。

## Acceptance Criteria

- [ ] `EvaluationRunner` 支持 L4 指标：Completion Rate / Human Intervention Count / Time Reduction / End-to-End Accuracy / First-Pass Yield
- [ ] 工作流执行全链路计时（per Agent + 总耗时）
- [ ] 自动对比 Baseline（GPT-4 Direct / Naive RAG / 纯人工估算）
- [ ] CI 集成：Completion Rate < 0.70 或 End-to-End Accuracy < 0.80 → PR Blocked
- [ ] L4 Report 含全链路 Trace（每个 Agent 的执行时间、tokens、产出、是否触发 HITL）
- [ ] 支持 A/B 对比（不同 Prompt 版本 / Agent 配置下的 L4 指标对比）

```python
# L4 Evaluation Result Schema
class L4EvaluationResult(BaseModel):
    case_id: str
    workflow_id: str
    metrics: L4Metrics
    agent_trace: list[AgentTraceEntry]
    hitl_events: list[HITLEvent]
    passed: bool
    baseline_comparison: BaselineComparison

class L4Metrics(BaseModel):
    completion_rate: float                  # 此 Case 是否完成（1 or 0）
    human_intervention_count: int           # HITL 触发次数
    time_reduction_ratio: float             # vs 纯人工
    end_to_end_accuracy: float              # vs 标注结论
    first_pass_yield: float                 # Reviewer 一次通过 (1 or 0)

class AgentTraceEntry(BaseModel):
    agent_name: str
    duration_ms: int
    tokens: int
    cost: float
    artifact_id: str | None
    next_action: str

class HITLEvent(BaseModel):
    agent_name: str
    reason: str
    decision: str                           # APPROVED | REJECTED | NEEDS_REVISION
    duration_ms: int                        # HITL 等待时间

class BaselineComparison(BaseModel):
    gpt4_direct_accuracy: float
    naive_rag_accuracy: float
    auditflow_accuracy: float
    improvement_vs_naive_rag: float         # AuditFlow / Naive RAG
```

```sql
-- L4 评估结果持久化表
CREATE TABLE evaluation_l4_result (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    case_id VARCHAR NOT NULL,
    workflow_id UUID NOT NULL,
    metrics JSONB NOT NULL,                -- L4Metrics
    agent_trace JSONB NOT NULL,            -- AgentTraceEntry[]
    hitl_events JSONB DEFAULT '[]',        -- HITLEvent[]
    baseline_comparison JSONB,             -- BaselineComparison
    passed BOOLEAN NOT NULL,
    evaluated_at TIMESTAMPTZ DEFAULT now()
);

CREATE INDEX idx_eval_l4_case ON evaluation_l4_result (case_id);
CREATE INDEX idx_eval_l4_workflow ON evaluation_l4_result (workflow_id);
```
