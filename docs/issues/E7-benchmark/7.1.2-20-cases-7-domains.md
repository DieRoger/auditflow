# 7.1.2 — 20 Cases × 7 领域
- **Epic:** E7 Benchmark Expansion
- **Labels:** `benchmark`, `data`, `test-cases`
- **Depends on:** 7.1.1 Benchmark Schema

## Description
基于 7.1.1 定义的 Benchmark Schema，构建覆盖 7 个审计领域、共 20 个 Benchmark Case 的业务数据资产。每个 Case 必须包含模拟审计文档、结构化 input 数据、以及经人工审核的 expected output。覆盖范围需满足 Risk Matrix 覆盖率要求（Grill #2 修正），且至少覆盖 5 个 E1B Reasoning Chain。

## Acceptance Criteria
- [ ] 每个 Case 含模拟文档（PDF/文本） + `input` 结构化数据 + `expected` output
- [ ] 覆盖 ≥5 个 E1B Reasoning Chain（如 Revenue Recognition Chain、AR Impairment Chain 等）
- [ ] 格式符合 7.1.1 Benchmark Schema 及 EvaluationRunner 输入规范
- [ ] 每个 Case 的 expected output 经人工审核确认
- [ ] 领域覆盖完整，无缺失

## I/O Interface / Schema
### 领域分布

| 领域 | Cases | 核心风险 |
|------|-------|----------|
| Revenue Recognition | 5 | 激进确认、截止性、虚构收入、捆绑合同、可变对价 |
| AR Impairment | 3 | 坏账准备不足、账龄分类错误、虚构应收 |
| Inventory Valuation | 3 | 存货跌价、数量差异、成本核算错误 |
| Expense Cutoff | 3 | 费用资本化、跨期费用、关联方交易 |
| Fixed Asset | 2 | 折旧政策变更、减值测试缺失 |
| Control Testing | 2 | 职责分离缺失、审批绕过 |
| Fraud Risk | 2 | 管理层凌驾、收入舞弊 |

### Case ID 命名规范
- Revenue Recognition: `rev_001` ~ `rev_005`
- AR Impairment: `ar_001` ~ `ar_003`
- Inventory Valuation: `inv_001` ~ `inv_003`
- Expense Cutoff: `exp_001` ~ `exp_003`
- Fixed Asset: `fa_001` ~ `fa_002`
- Control Testing: `ctrl_001` ~ `ctrl_002`
- Fraud Risk: `fraud_001` ~ `fraud_002`
