# 5.2.1 — 响应式布局 + 三态覆盖（Responsive Layout + Three-State Coverage）
- **Epic:** E5 Product Experience
- **Labels:** `frontend`, `responsive`, `ux`, `loading-states`, `react`
- **Depends on:** 5.1.1 (Main Dashboard), 5.1.2 (Project Management Page), E1A–E4 各前端页面

## Description

建立全局响应式布局系统和三态（Loading / Empty / Error）覆盖规范，确保 AuditFlow 所有前端页面在桌面端、平板端、移动端均有良好的交互体验，且每个数据驱动的 UI 模块在所有状态下都有明确的视觉反馈。

**这不是一个独立页面，而是横切关注点（Cross-Cutting Concern），作用于 E1A 到 E4 所有前端 Issue 产出的页面。**

### Part A — 响应式布局系统

定义三个断点（Breakpoints）及对应的布局策略：

| 断点 | 宽度 | 设备 | 布局策略 |
|------|------|------|----------|
| **Desktop** | ≥ 1280px | 桌面显示器 | 多栏布局（2–4 列），侧边栏常驻，充分利用横向空间 |
| **Tablet** | 768–1279px | iPad / 小型笔记本 | 栏数缩减（≤ 2 列），侧边栏可折叠，堆叠优先级 |
| **Mobile** | < 768px | 手机 | 单栏布局，关键操作置底（Bottom Sheet / FAB），导航转为汉堡菜单 |

核心规则：
```
┌─────────────────────────────────────────────────────┐
│ Desktop (≥1280px)                                    │
│ ┌──────────┬──────────────────┬────────────────────┐ │
│ │ 侧边导航   │ 主内容区           │ 辅助面板（可选）    │ │
│ │ 常驻 240px│                  │ 320px             │ │
│ └──────────┴──────────────────┴────────────────────┘ │
├─────────────────────────────────────────────────────┤
│ Tablet (768–1279px)                                  │
│ ┌──────────┬────────────────────────────────────────┐ │
│ │ 侧边导航   │ 主内容区（全宽）                        │ │
│ │ 可折叠    │                                        │ │
│ │ 60px     │                                        │ │
│ └──────────┴────────────────────────────────────────┘ │
│ 辅助面板 → Drawer（从右侧滑出）                         │
├─────────────────────────────────────────────────────┤
│ Mobile (<768px)                                      │
│ ┌──────────────────────────────────────────────────┐  │
│ │ 顶部导航栏（汉堡菜单 + 页面标题）                    │  │
│ ├──────────────────────────────────────────────────┤  │
│ │ 主内容区（单栏滚动）                                │  │
│ │                                                  │  │
│ │                                                  │  │
```

### Part B — 三态覆盖规范

每个数据驱动 UI 模块（列表、卡片、图表、详情面板）必须覆盖三种状态：

| 状态 | 触发条件 | 设计模式 |
|------|----------|----------|
| **Loading** | 数据正在获取中（首次加载 + 后续刷新） | 骨架屏（Skeleton / Shimmer），保持布局稳定，避免 CLS |
| **Empty** | 数据返回空集（无项目、无风险、无审批等） | 居中插画 + 说明文案 + CTA 引导按钮（如"创建第一个项目"） |
| **Error** | 网络错误、超时、5xx、权限不足等 | 错误信息 + "重新加载"按钮 + 错误详情可展开（仅开发模式） |

**三态优先级与切换规则：**
```
  Loading ──→ Empty ──→ Data（正常渲染）
     │          │
     └──→ Error ←──┘（Loading 失败 或 后续刷新失败）
                │
                └──→ 重试成功 → Loading → Data
```

**页面级三态清单（每个页面 Issue 均需覆盖）：**

| 页面 | Loading | Empty | Error |
|------|---------|-------|-------|
| Main Dashboard（5.1.1） | 4 KPI 卡片骨架 + 时间线骨架 | "欢迎使用 AuditFlow — 上传第一个文档开始审计" | 全局错误插图 + 重试 |
| Project Management（5.1.2） | 列表 5 行骨架屏 | "创建第一个审计项目" CTA | 列表错误 + 重试 |

| Knowledge Explorer（E1B） | 搜索框 + 结果区骨架 | 搜索无结果 "未找到匹配准则" | 搜索错误 + 重试 |

**模块级独立错误处理：**
- 页面中的每个独立数据模块（如 Dashboard 的 4 张 KPI 卡片）应有独立的 Error 边界
- 一个模块加载失败不影响其余模块渲染
- 每个模块有自己的 "重试" 按钮（仅重试该模块的请求）

## Acceptance Criteria

### 响应式布局
- [ ] **三个断点实现：** 使用 CSS 媒体查询或 Tailwind breakpoints（`lg:` ≥1280px, `md:` 768–1279px, `sm:` <768px），断点值与设计规范一致
- [ ] **全局布局组件：** 实现 `AppShell` 组件（侧边导航 + 顶栏 + 主内容区 + 可选辅助面板），自动适配断点
- [ ] **侧边导航栏：** Desktop 常驻 240px；Tablet 折叠为 60px（仅图标）；Mobile 隐藏，通过汉堡菜单打开全屏 Drawer
- [ ] **表格/列表响应式：** Desktop 完整列展示；Tablet 隐藏次要列；Mobile 转为卡片列表（Card List）布局
- [ ] **多栏布局降级：** 2–4 栏在 Tablet 降为 ≤ 2 栏，Mobile 降为单栏堆叠
- [ ] **移动端底部操作栏：** 关键操作（新建、搜索、筛选）固定在底部，避免隐藏在滚动区域下方
- [ ] **触控友好：** 所有可点击元素最小 44×44px 触控区域（Mobile）；按钮间距 ≥ 8px 防误触
- [ ] **字体缩放：** 使用 `rem` / `em` 相对单位，支持浏览器字体缩放至 200% 不破坏布局
- [ ] **所有 E1A–E4 页面通过响应式验收：** 在 1920px / 1024px / 375px 三种视口下无横向滚动条、无重叠、无截断

### 三态覆盖
- [ ] **Loading 骨架屏组件库：** 提供 `SkeletonCard`、`SkeletonList`（N 行）、`SkeletonChart`（矩形/圆形占位）、`SkeletonTable`（M 列 × N 行）通用骨架组件
- [ ] **骨架屏匹配布局：** 骨架屏与真实内容布局一致（宽度/高度/间距），避免加载完成后的 Cumulative Layout Shift（CLS）
- [ ] **Empty 状态组件：** 提供 `<EmptyState icon={...} title="..." description="..." action={...} />` 通用组件，每个页面根据上下文定制文案和 CTA
- [ ] **Error 状态组件：** 提供 `<ErrorState message="..." onRetry={...} detail={...} />` 通用组件，支持展开技术细节（开发模式）
- [ ] **Error Boundary：** 每个页面包裹 React Error Boundary，捕获渲染异常后显示 Error 状态而非白屏
- [ ] **模块级独立 Error：** 页面内各数据模块使用独立 Error Boundary + 独立重试，单一模块失败不级联
- [ ] **网络状态感知：** 使用 `navigator.onLine` + online/offline 事件，离线时显示"网络已断开"全局 Banner
- [ ] **所有页面 Issue 的 AC 中均已引用本 Issue 的三态要求**（Backend Capability First Rule 延伸——前端状态覆盖 First）
- [ ] **E2E 测试覆盖：** 每个页面至少 3 个测试用例（Loading 骨架可见 → Empty 状态正确 → Error 重试恢复）

## I/O Interface

本 Issue 不定义新的 API Contract，而是定义共享前端组件和 Hook 的接口：

```typescript
// 共享组件接口

// 骨架屏组件族
interface SkeletonProps {
  lines?: number;          // 骨架行数（SkeletonList）
  width?: string;          // CSS 宽度
  height?: string;         // CSS 高度
  className?: string;
}

// EmptyState 组件
interface EmptyStateProps {
  icon?: React.ReactNode;       // 插画图标
  title: string;                // "暂无审计项目"
  description?: string;         // 引导文案
  action?: {
    label: string;              // CTA 按钮文字
    onClick: () => void;
  };
}

// ErrorState 组件
interface ErrorStateProps {
  message: string;              // 用户友好的错误信息
  onRetry: () => void;          // 重试回调
  detail?: string;              // 技术细节（开发模式可展开）
  statusCode?: number;          // HTTP 状态码
}

// 响应式 Hook
function useBreakpoint(): "desktop" | "tablet" | "mobile";
function useMediaQuery(query: string): boolean;

// 异步数据 Hook（内置三态管理）
function useAsyncData<T>(
  fetcher: () => Promise<T>,
  deps?: any[]
): {
  data: T | null;
  loading: boolean;
  error: Error | null;
  retry: () => void;
};
```

## UI States（本 Issue 自身的状态检查）

| 状态 | 表现 |
|------|------|
| **响应式验收 — Desktop** | 1920px 视口：侧边栏 240px + 主内容 + 辅助面板 320px；表格完整列；多栏 KPI |
| **响应式验收 — Tablet** | 1024px 视口：侧边栏折叠 60px；表格隐藏次要列；2 栏降级 |
| **响应式验收 — Mobile** | 375px 视口：单栏；卡片列表替代表格；底部操作栏固定；汉堡菜单 |
| **Loading 验收** | 每个页面的骨架屏与最终渲染布局像素级匹配，无 CLS |
| **Empty 验收** | 每个页面的空状态有明确 CTA，引导用户下一步操作 |
| **Error 验收** | 每个页面的错误状态有重试按钮；模块级错误不影响其余模块；Error Boundary 无白屏 |
