# 5.2.2 — 暗色模式 + 无障碍访问（Dark Mode + a11y）
- **Epic:** E5 Product Experience
- **Labels:** `frontend`, `a11y`, `dark-mode`, `wcag`, `accessibility`, `react`
- **Depends on:** 5.2.1 (Responsive + Three-State), 5.1.1 (Main Dashboard), 5.1.2 (Project Management Page), E1A–E4 各前端页面

## Description

建立暗色模式（Dark Mode）主题系统和 WCAG 2.1 AA 级无障碍访问（a11y）规范，确保 AuditFlow 前端对所有用户（包括使用辅助技术的审计师）均可访问且视觉舒适。这两个关注点共享 CSS 变量 / Design Token 基础设施，因此合并为一个 Issue。

**这同样是横切关注点（Cross-Cutting Concern），作用于 E1A 到 E4 所有前端页面。**

### Part A — 暗色模式（Dark Mode）

基于 CSS 自定义属性（CSS Custom Properties / Design Tokens）实现主题切换，避免运行时样式重复计算。

**主题 Token 体系：**

**主题切换行为：**
```
┌─────────────────────────────────────────────┐
│ 主题切换策略                                  │
├─────────────────────────────────────────────┤
│ 1. 首次加载 → 读取系统偏好 (prefers-color-   │
│    scheme: dark) → 设置初始主题              │
│ 2. 用户手动切换 → 存入 localStorage           │
│    ("auditflow-theme": "dark" | "light")    │
│ 3. localStorage > 系统偏好 > 默认亮色        │
│ 4. 切换时 CSS 变量瞬间生效（无闪烁）           │
│ 5. 图表/可视化组件颜色同步切换                 │
└─────────────────────────────────────────────┘
```

### Part B — 无障碍访问（a11y — WCAG 2.1 AA）

目标：所有前端页面对屏幕阅读器（Screen Reader）用户和仅键盘操作用户完全可用。审计行业用户群体中存在对无障碍有刚性需求的审计师，不是"锦上添花"。

**a11y 检查清单（按 WCAG 2.1 AA 成功标准）：**

| 标准 | 要求 | 适用范围 |
|------|------|----------|
| **1.1.1 Non-text Content** | 所有 `<img>` 有 `alt`；SVG 图标有 `aria-label`；图表有文本替代 | 全部页面 |
| **1.3.1 Info and Relationships** | 表格用 `<th scope>`；表单用 `<label>`；分组用 `<fieldset><legend>` | 全部页面 |
| **1.3.2 Meaningful Sequence** | DOM 顺序 = 视觉阅读顺序 | 全部页面 |
| **1.4.1 Use of Color** | 颜色不是传达信息的唯一方式（风险等级除颜色外还需文字 Badge + 图标） | Risk Page / Dashboard |
| **1.4.3 Contrast (Minimum)** | 普通文本 4.5:1；大文本 3:1；UI 组件 3:1 | 全部页面（亮色+暗色） |
| **1.4.11 Non-text Contrast** | 图表元素、焦点指示器、输入边框 ≥ 3:1 | 全部页面 |
| **2.1.1 Keyboard** | 所有交互元素可通过键盘操作（Tab/Shift+Tab/Enter/Escape/Arrow） | 全部页面 |
| **2.1.2 No Keyboard Trap** | 键盘焦点不会困在模态框/下拉菜单内（Escape 关闭） | Modal / Drawer / Dropdown |
| **2.2.2 Pause, Stop, Hide** | 自动动画 > 5 秒需暂停/停止控件 | Loading 动画 |
| **2.3.1 Three Flashes** | 无每秒 3 次以上闪烁的内容 | 全部页面 |
| **2.4.2 Page Titled** | 每个页面有描述性 `<title>` | 全部页面 |
| **2.4.3 Focus Order** | Tab 顺序符合视觉逻辑 | 全部页面 |
| **2.4.4 Link Purpose** | 链接文本可独立理解（非"点击这里"） | 全部页面 |
| **2.4.7 Focus Visible** | 所有可聚焦元素有可见焦点指示器（2px 外边框或阴影偏移） | 全部页面 |
| **3.1.1 Language of Page** | `<html lang="zh-CN">` | 全局 |
| **3.2.1 On Focus** | 聚焦不触发上下文变化（不自动提交表单、不自动跳转） | 全部页面 |
| **3.3.1 Error Identification** | 表单验证错误用文本描述（非仅红色边框） | Modal / Form |
| **3.3.2 Labels or Instructions** | 所有输入框有可见 Label | Modal / Form |
| **4.1.1 Parsing** | HTML 有效（无重复 ID、正确嵌套） | 全部页面 |
| **4.1.2 Name, Role, Value** | 自定义组件暴露正确的 ARIA role/name/value | 全部自定义组件 |
| **4.1.3 Status Messages** | Toast / 通知用 `role="status"` 或 `aria-live` | Toast / Notification |

**ARIA 标注示例：**
```html
<!-- 骨架屏：标记为加载中 -->
<div role="status" aria-label="加载中" aria-busy="true">
  <div class="skeleton-card"></div>
</div>

<!-- 风险等级 Badge：纯颜色 → 颜色 + 文字 + 图标 -->
<span class="badge badge-high" role="img" aria-label="高风险">
  ⚠️ HIGH
</span>

<!-- 动态内容区域：屏幕阅读器自动播报变更 -->
<div aria-live="polite" aria-atomic="true">
  <!-- WebSocket 实时推送的审批通知 -->
</div>

<!-- 模态框：焦点陷阱 + Escape 关闭 -->
<div role="dialog" aria-modal="true" aria-labelledby="modal-title">
  <h2 id="modal-title">新建审计项目</h2>
  <!-- 焦点自动移到第一个可聚焦元素；Tab 在模态框内循环 -->
</div>

<!-- 可展开/折叠区域 -->
<button aria-expanded="true" aria-controls="reasoning-panel">
  展开推理链
</button>
<div id="reasoning-panel" role="region" aria-label="Agent 推理链">
  ...
</div>
```

## Acceptance Criteria

### 暗色模式
- [ ] **Design Token 体系：** 所有颜色、阴影、边框颜色通过 CSS 自定义属性定义（零硬编码颜色值），在 `:root` 和 `[data-theme="dark"]` 下各有一套完整 Token
- [ ] **<html> 标签挂载 `data-theme` 属性：** `<html data-theme="dark">` 或 `<html data-theme="light">`，由 ThemeProvider 管理
- [ ] **系统偏好检测：** 首次加载时读取 `window.matchMedia('(prefers-color-scheme: dark)')`，自动匹配系统主题
- [ ] **手动切换持久化：** 用户通过 UI 切换主题 → `localStorage.setItem("auditflow-theme", ...)` → 下次访问优先读取 localStorage
- [ ] **无闪烁切换（Flash-Free）：** 在 `<head>` 中注入阻塞脚本读取 localStorage/系统偏好，在页面渲染前设置 `data-theme`，避免亮→暗闪烁
- [ ] **切换控件：** 顶部导航栏提供主题切换按钮（☀️/🌙 图标），支持三态：亮色 / 暗色 / 跟随系统
- [ ] **图表颜色同步：** Recharts / React Flow 等可视化组件的颜色通过 CSS 变量引用，主题切换时图表即时更新
- [ ] **所有 E1A–E4 页面在两种主题下验收通过：** 对比度、可读性、视觉层次无退化

### 无障碍访问（a11y）
- [ ] **Lighthouse Accessibility 得分 ≥ 95：** 每个页面在 Chrome DevTools Lighthouse 审计中 Accessibility 分数 ≥ 95
- [ ] **axe-core 自动化检查通过：** CI 集成 `@axe-core/react` 或 `jest-axe`，PR 中新增 a11y 违规阻止合并
- [ ] **键盘导航完整覆盖：** 所有页面可通过键盘完成核心操作流程（Tab 导航 → Enter 激活 → Escape 关闭 → Arrow 选择），无鼠标依赖
- [ ] **焦点指示器：** 所有可聚焦元素有可见焦点环（`outline: 2px solid var(--color-accent); outline-offset: 2px`），不使用 `outline: none` 除非提供更明显的替代方案
- [ ] **焦点顺序合理：** Tab 键按从左到右、从上到下的视觉逻辑移动；模态框打开时焦点移入模态框，关闭时焦点回到触发元素
- [ ] **屏幕阅读器兼容：** 使用 NVDA（Windows）/ VoiceOver（macOS）验证核心流程可完整操作
- [ ] **Skip Link：** 页面顶部提供"跳到主内容"（Skip to Main Content）隐藏链接，Tab 聚焦时显示
- [ ] **语义化 HTML：** 使用 `<nav>`、`<main>`、`<aside>`、`<header>`、`<footer>`、`<section>`、`<article>` Landmark 元素，不使用 `<div>` 模仿
- [ ] **表单无障碍：** 所有 `<input>` / `<select>` / `<textarea>` 有关联 `<label>`；必填字段标记 `aria-required="true"`；错误信息关联 `aria-describedby`
- [ ] **动态内容通知：** Toast / 通知使用 `role="status"` + `aria-live="polite"`；关键错误（审批失败等）使用 `aria-live="assertive"`
- [ ] **颜色对比度达标：** 所有文本/UI 组件在亮色和暗色主题下均满足 WCAG AA 对比度（普通文本 4.5:1、大文本 3:1、UI 组件 3:1）
- [ ] **非颜色信息传达：** 风险等级、状态标签除颜色外还包含文字 + 图标；图表除颜色外还包含数据标签或图案（Pattern Fill）
- [ ] **动画控制：** 尊重 `prefers-reduced-motion: reduce` 媒体查询，关闭非必要动画和转场效果
- [ ] **页面标题：** 每个页面 `<title>` 格式为 `{页面名} — AuditFlow`（如"风险评估 — AuditFlow"）

## I/O Interface

本 Issue 定义 Design Token 结构和 a11y 工具链配置：

```typescript
// 主题 Context
interface ThemeContextValue {
  theme: "light" | "dark" | "system";
  resolvedTheme: "light" | "dark";     // system 解析后的实际值
  setTheme: (theme: "light" | "dark" | "system") => void;
  toggleTheme: () => void;
}

// ThemeProvider Props
interface ThemeProviderProps {
  children: React.ReactNode;
  defaultTheme?: "light" | "dark" | "system";
  storageKey?: string;                  // localStorage key，默认 "auditflow-theme"
}

// CSS Design Token 类型（供 Tailwind 扩展参考）
// 所有 Token 通过 CSS 变量定义，Tailwind config 引用：
// tailwind.config.ts
//   colors: {
//     'bg-primary': 'var(--color-bg-primary)',
//     'text-primary': 'var(--color-text-primary)',
//     ...
//   }
```

**无新 API Contract — 本 Issue 纯前端基础设施。**

## UI States（暗色模式切换）

| 状态 | 表现 |
|------|------|
| **首次加载（无 localStorage）** | 读取系统 `prefers-color-scheme`；瞬间应用对应主题；无闪烁 |
| **localStorage 已存储** | 读取 `auditflow-theme`；在 `<head>` 阻塞脚本中设置 `data-theme` |
| **用户切换 → 暗色** | 所有组件颜色即时过渡（CSS 变量替换，无重新渲染）；localStorage 写入 "dark"；图标切换为 🌙 |
| **用户切换 → 跟随系统** | 清除 localStorage 中主题键；恢复 `matchMedia` 监听；图标切换为 ⚙️ |
| **系统主题变化（macOS 自动切换）** | `matchMedia` 事件监听 → 当用户设置为"跟随系统"时自动切换；用户手动设置时不跟随 |
| **图表在暗色模式** | Recharts 轴线/标签颜色切换为浅色；React Flow 背景色切换；Tooltip 背景色适配 |
