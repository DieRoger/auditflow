# 3.3.1 — 端到端闭环验证
- **Epic:** E3 Agent Core Runtime
- **Labels:** `agent`, `integration`, `e2e`
- **Depends on:** 3.2.1 (Planner), 3.2.2 (Knowledge), 3.2.3 (Risk), 3.2.4 (Evidence), 3.2.5 (Reviewer)

## Description

完成 Planner → Knowledge → Risk → Evidence → Reviewer → HITL 的端到端闭环验证。这是 E3 的集成里程碑 —— 5 个 Agent 在 Workflow Engine 调度下，按 Ontology 推理链协作完成一次完整的审计工作流，最终到达 WAITING_APPROVAL（人工审批节点）。

**完整闭环流程：**
```
用户上传文档 + 审计目标
    ↓
[1] Planner Agent
    ├── 查询 Ontology → 匹配 Reasoning Chains
    ├── 拆解子任务 → AuditPlanArtifact
    └── next_action="KNOWLEDGE_AGENT"
    ↓
[2] Knowledge Agent
    ├── 检索审计准则 → KnowledgePackageArtifact
    └── next_action="EVIDENCE_AGENT"
    ↓
[3] Evidence Agent
    ├── Hybrid Search 客户文档 → EvidencePackageArtifact
    └── next_action="RISK_AGENT"
    ↓
[4] Risk Agent（可能迭代 ≤3 次）
    ├── 匹配 Risk Indicators → 评估 Severity
    ├── 证据不足？→ 退回 Evidence → 重新收集（iteration）
    ├── 证据充分 → RiskFindingArtifact
    ├── HIGH/CRITICAL？→ next_action="HUMAN_REVIEW"
    └── 否则 → next_action="REVIEWER_AGENT"
    ↓
[5] Reviewer Agent
    ├── 审查全部 Artifact → ReviewReportArtifact
    ├── APPROVED → next_action="HUMAN_REVIEW"
    └── NEEDS_REVISION → 退回指定 Agent（重跑循环）
    ↓
[6] WAITING_APPROVAL（HITL 状态）
    ├── 人工审批 → APPROVED/REJECTED/MODIFY
    └── 工作流 → COMPLETED
```

## Acceptance Criteria

- [ ] 至少 3 条完整推理链（revenue_recognition / ar_impairment / inventory_valuation）通过端到端闭环
- [ ] Risk Agent 迭代循环验证：Evidence 不足 → 退回补充 → Risk 重新评估（≥1 个 Case 触发此路径）
- [ ] HITL 审批闭环验证：WAITING_APPROVAL → APPROVED → 工作流 COMPLETED
- [ ] Reviewer 退回验证：NEEDS_REVISION → 退回 Risk → Risk 修正 → Reviewer 再次审查 → APPROVED（≥1 个 Case 触发）
- [ ] 全部 16 种 Event 在工作流中触发并持久化到 Audit Log
- [ ] 端到端执行时间 ≤ 10 分钟（含 LLM 调用，不含人工审批等待）
- [ ] Artifact 溯源链完整性：所有 Artifact 的 `parent_artifact_id` 可追溯到 AuditPlanArtifact

## Evaluation

| L4 指标 | 说明 | 目标 |
|---------|------|------|
| **Completion Rate** | 闭环完成率（不中断到达 COMPLETED 或 WAITING_APPROVAL） | ≥ 0.90 |
| **Human Intervention Count** | 平均人工干预次数 | ≤ 2 次 / Workflow |
| **E2E Duration** | 端到端执行时间（不含人工等待） | ≤ 10 min |
